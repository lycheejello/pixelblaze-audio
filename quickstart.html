Before you start

Pixelblazepowered on, on the same wifi as this computer, and you know its IP (the Pixelblaze web UI shows it)
Chromethe reliable browser for tab-audio capture
musicplaying in a Chrome tab — or through a virtual audio device for desktop apps / offline

The four steps

1
Put a reactive pattern on the Pixelblaze — and make it active.

Open the Pixelblaze web UI → new pattern → paste one of the files from patterns/ → save → click it so it's the pattern currently running.

Why it matters: setVars only reaches the active pattern. If the wrong pattern is running, everything below will look connected and nothing will react.

Start with reactive.js (uses the four scalars) or spectrum.js (uses the bands array — its NBANDS must equal the app's bands slider).

2
Start the app.

From the project folder:

$ ./run.sh serving /Users/you/pixelblaze-audio → http://localhost:8000/index.html → http://192.168.0.20:8000/index.html (phone / other machine) ctrl-c to stop

It opens Chrome for you. ./run.sh 9000 picks another port.

http, not https. The Pixelblaze speaks plain ws://, and an https page blocks that as mixed content. Always load the app over http://.
3
Connect to the Pixelblaze.

Type its IP, hit Connect. Green dot = the socket is open.

Pixelblaze 192.168.0.65 Connect connected
4
Start audio — and tick Share audio.

Hit Start audio, then in Chrome's picker choose the tab that's playing music and turn on the audio toggle. No tick = a silent track = flat lights.

What the sliders do

sliderturn it up when…
gainthe lights barely move — it scales everything before sending. Too high = permanently pinned at full.
smoothingthe response is twitchy. Higher = smoother, laggier. Lower = snappier, jitterier.
send ratemotion looks steppy (more frames/sec to the device). Lower it if the Pixelblaze feels sluggish.
bandsyou want a finer spectrum — must match NBANDS in the pattern on the device.
beat sensyou're getting phantom beats (higher = stricter). The pink dot flashes on each detected hit.

leveloverall loudness, 20 Hz–16 kHz
bandsarray of N log-spaced bands across 20 Hz–16 kHz
beatsnaps to 1 on a bass onset, decays to 0

All six arrive in one frame: {"setVars": {"bass":0.2, …, "bands":[…], "beat":0}}. Write your own pattern against any of them — the app doesn't care what they drive.

Picking a pattern

Use the app's strip preview dropdown to audition every pattern against whatever's playing before you touch the hardware.

patternplays best with
reactive.jsall-rounder — pop, rock, most electronic
spectrum.jsdetailed mixes — orchestral, jazz, IDM
spectrum-mirror.jscenter-mounted strips — bass blooms from the middle
beat.jsa steady, clear kick — house, techno, hip-hop
beat-pump.jsbass-forward — dubstep, trap, DnB
vu-bar.jsdynamic material — rock, live sets, big drops
plasma.jsbeatless & smooth — ambient, downtempo, classical
sparkle.jsbright highs — acoustic, jazz, hi-hat-heavy EDM
starfield.js2D star ceiling (needs a pixel map) — ambient, drone, a chant loop

Two-strip patterns (Output Expander) and the full notes live in the README.

When it doesn't work

symptomfix
won't connectSame wifi? Right IP? On this machine, a Tailscale exit node tunnels LAN traffic and kills the route — set Exit Node → None (disconnecting Tailscale isn't the fix).
connected, nothing movesThe reactive pattern isn't the active one on the device. setVars only reaches what's running.
meters flatNo audio in the captured track — re-share and tick Share audio; on macOS share a Chrome tab, not a window or screen.
connection refused / blockedThe page is on https. Serve it over http (that's what ./run.sh does).
only part of the strip lightsThe app's bands count ≠ NBANDS in spectrum.js. Only the overlap updates; make them equal.
lights pinned / barely twitchTurn gain down / up. It's the first knob to reach for.
